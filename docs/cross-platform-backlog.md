# Кросс-платформенный бэклог

Фичи, которые есть в `competra-android`, но ещё не перенесены в `competra-web` (и наоборот). См. раздел «Межпроектные связи» в [CLAUDE.md](../CLAUDE.md) — обе платформы покрывают одну доменную область, парность фич поддерживается вручную через этот файл.

Последний аудит: 12 августа 2026. Реализация пунктов 1/2/3/6 из первой версии аудита: 13 августа 2026.

## Реализовано (для истории)

- **Таблица сплитов группы** и **график отставания от лидера (race graph)** — реализованы в `f65f4fe` (`GroupSplitsTablePage.kt`, `RaceGraphPage.kt`). Ранее в этом файле числились как «не реализовано» — запись устарела, актуальная логика теперь только в коде.
- **Живые результаты (автообновление)** — тоже реализовано в `f65f4fe`, тем же коммитом (`ResultsTab.kt:36-37,72-79,108-116`: поллинг каждые 30с пока `competitionStatus in {IN_PROGRESS, STARTED}`, live-индикатор). При аудите 12.08.2026 запись «не реализовано» попала в этот файл из-за слишком узкого grep-паттерна — фактически фича была готова уже с 13 июля.
- **Публикация результатов** (`resultsStatus` → `OFFICIAL`) — реализовано 13.08.2026: кнопка на `ManageCompetitionPage.kt` (вкладка «Результаты»), апдейт через существующий upsert `CompetitionRepository.createCompetition()` с полным набором полей соревнования (чтобы не затереть остальные поля, как было в баге Android SEN-95 с группами).
- **Score-O («по выбору», BY_CHOICE)** — реализовано 13.08.2026: `ParticipantGroupDetail`/`CreateGroupRequest` получили `timeLimitMinutes`/`scorePenaltyPerMinute`/`maxLatenessMinutes` (дефолты 60/1/30, как на Android); ввод баллов на КП через формат `номер:баллы` в `CreateDistanceDialog`/`DistanceDialog` (общая функция `parseControlPoints()` в `DistancesTab.kt`); `ResultsTab.kt` показывает колонку «Очки» и скрывает переходы к сплитам/race graph, когда `direction == "BY_CHOICE"`. **Важно**: `SplitsTableBuilder.kt` трогать не понадобилось — ранжирование (`OrienteeringResult.rank`) и сумма баллов (`totalScore`) уже приходят готовыми с бэкенда, композитный ключ ранжирования (баг SEN-95) — это исключительно локальная offline-логика Android-синхронизации, у web такого слоя нет. Известное ограничение: `CompetitionDetail.direction` (публичный эндпоинт для анонимных/незалогиненных посетителей) дефолтится в `"FORWARD"`, если бэкенд не присылает поле — не проверено, отдаёт ли его реально бэкенд на этом эндпоинте.
- **Удаление аккаунта + согласие на обработку ПДн** — реализовано 13.08.2026: `AuthRepository.deleteAccount()` (`DELETE user/me`, использует уже существующий authClient с Bearer-токеном) + кнопка «Удалить аккаунт» с подтверждением в `ProfilePage.kt`. Чекбокс согласия — на `LoginPage.kt`, блокирует кнопку «Получить код» (поскольку в web нет отдельного экрана регистрации — вход и создание аккаунта происходят одним email+code флоу, чекбокс поставили на единственный существующий «формообразующий» шаг). Ссылка «Политика конфиденциальности» под чекбоксом реально кликабельна только при входе со страницы профиля (`ProfilePage` → `onPrivacyClick` прокинут) — на остальных 6 местах, где `LoginPage` всплывает как гейт (клубы, дневник, рейтинги, создание клуба, управление, тренировки), параметр не прокинут и ссылка не активна; сам чекбокс/гейт работает везде одинаково, это чисто визуальный доводок при желании.

## Не реализовано в Web

### 1. Жеребьёвка участников (Draw)

**Статус**: не реализовано. Реализовано в `competra-android` (`DrawViewModel.kt`, `feature/center/.../draw/`).

**Что нужно**: инструмент организатора, назначающий `startNumber` + `startTime` всем участникам соревнования. Три режима (все реализованы как чистые функции, легко переносимы в `:shared`):
- **Общая жеребьёвка** — участники перемешиваются с чередованием групп (подряд не стартуют двое из одной группы), время = `competitionStartTime + позиция × startIntervalSeconds`.
- **По группам** — перемешивание независимо внутри каждой группы, участники из разных групп могут стартовать одновременно.
- **По дистанциям** (`drawParticipantsByDistance`, самый сложный режим) — на один стартовый слот не более одной дистанции и не более `corridors` участников, старты одной дистанции разнесены минимум на `gap` слотов и равномерно растянуты по всему расписанию (жадный алгоритм с целевыми слотами + добором при коллизии).

Для `PunchingSystem.SPORTIDUINO` номер чипа приравнивается к стартовому номеру — в web этой системы отметки нет, это условие можно не переносить.

**Референс**: `feature/center/src/main/java/com/competra/center/presentation/draw/DrawViewModel.kt`, юнит-тесты — `feature/center/src/test/java/com/competra/center/DrawByDistanceTest.kt`.

### 2. Стартовая решётка (Start Grid)

**Статус**: не реализовано. Реализовано в `competra-android` (`StartGridScreen`/`StartGridViewModel.kt`).

**Что нужно**: экран организатора — участники, уже прошедшие жеребьёвку (см. п.1), группируются по `startTime` в минутные слоты; во время гонки (`status == IN_PROGRESS`) ведётся живой секундомер, подсвечивающий ближайший ещё не стартовавший слот. Зависит от п.1 — без назначенных `startTime` показывать нечего.

## Платформенно-специфичное (не переносится, для справки)

- **Push-уведомления (FCM) + deep-links** (SEN-93) — мобильная инфраструктура; для web потребовался бы отдельный механизм (Web Push), решение по этому не принято.
- **NFC** (чтение/запись Sportiduino-чипов, фоновое сканирование, `OrienteeringEventControlScreen`) — Android-специфика, см. CLAUDE.md.
- **Живой GPS-трекинг тренировки** (`LiveTrackingScreen`) — сознательно не перенесён, см. Epic 6 в памяти проекта.
- **Онбординг** — сознательно закрыт как не нужный на вебе, см. Epic 7 в памяти проекта.
